# excerptStringPutback 仕様書

## 1. 目的

UTF-8 のテキストファイルから二重引用符で囲まれた文字列を抜粋し、抜粋ファイル上で編集した文字列を、元ファイルの同じ位置へ書き戻す。

excerptTextPutback と同じく、次の順で扱う。

1. 対象を入力ファイルから抜粋する。入力ファイルは変更しない。
2. 抜粋ファイルだけを編集する。
3. 書き戻す直前に、抜粋時の断片が入力のその位置に残っていることを確認する。
4. 確認できた断片だけを、編集後の文字列へ置き換える。

違いは対象である。excerptTextPutback のテキスト範囲に対して、このツールは二重引用符付きの文字列を対象にする。

## 2. 用語

| 語 | 意味 |
| --- | --- |
| 入力ファイル | 抜粋元の UTF-8 テキスト |
| 抜粋ファイル | 文字列の位置と内容を 1 行 1 件の JSON で並べたファイル |
| raw | 入力ファイル上の、引用符を含むそのままの断片 |
| edited | 書き戻す断片。引用符を残すかどうかもこの値どおり |
| start | 入力を UTF-8 として読んだ文字列上の、raw の開始位置。0 始まり |
| length | raw の長さ |

`start` と `length` の単位は、C# の `string` と同じ UTF-16 コードユニットである。通常の日本語は 1 文字が 1 である。サロゲートペアになる文字は 2 になる。UTF-8 の BOM は文字列に含めず、位置の計算にも入れない。

## 3. 抜粋する文字列

次の規則で、二重引用符 `"` から次の閉じ引用符までを 1 件とする。引用符自身も raw に含める。

- 文字列の内側では、バックスラッシュの直後の 1 文字をエスケープとして読み飛ばす。したがって `\"` は文字列を終わらせない。
- 閉じ引用符の手前でファイルが終わる、またはバックスラッシュでファイルが終わる場合はエラーにする。
- 引用符の外にある文字は抜粋しない。キーも値も、二重引用符で囲まれていればどちらも対象になる。
- 単一引用符、C# の逐語的文字列 `@"..."`, コメント、ヒアドキュメントは解釈しない。

空の文字列 `""` も 1 件である。length は 2 になる。

## 4. コマンド

```text
excerptStringPutback excerpt <入力ファイル> <抜粋ファイル>
excerptStringPutback putback <入力ファイル> <抜粋ファイル> <出力ファイル>
excerptStringPutback --help
```

終了コード:

| コード | 意味 |
| --- | --- |
| 0 | 成功。`--help`、`-h`、`help` も 0 |
| 1 | 引数の数が違う、または不明なコマンド。使い方を標準エラーへ出す |
| 2 | ファイルを読めない、UTF-8 でない、文字列が閉じていない、抜粋ファイルが不正、書き戻しの照合に失敗した |

成功時は標準出力へ件数と出力先を 1 行で出す。失敗時は標準エラーへ `エラー: ` に続けて理由を出す。

`excerpt` は抜粋ファイルと入力ファイルが同じパスのとき失敗する。`putback` は出力ファイルと抜粋ファイルが同じパスのとき失敗する。出力ファイルと入力ファイルが同じパスのときは、読み終えてからそのファイルを置き換える。

パスの一致は絶対パスで比べる。Windows では大文字小文字を区別しない。

## 5. ファイル形式

入力ファイルと出力ファイルは UTF-8 である。入力に UTF-8 BOM がある場合、出力にも BOM を付ける。BOM がない場合は付けない。改行コードは変換しない。

抜粋ファイルは UTF-8、改行は LF、BOM は付けない。読み込み時に先頭の UTF-8 BOM と空行は無視する。各行の前後の空白も無視する。

1 行目は meta 行とする。

```json
{"kind":"meta","tool":"excerptStringPutback","encoding":"utf-8","source":"input.txt"}
```

- `kind` は `meta`
- `tool` がある場合は `excerptStringPutback`
- `encoding` がある場合は `utf-8`
- `source` は excerpt に渡した入力パス。書き戻しでは参照しない

2 行目以降が文字列である。`id` は 1 から順に、欠番なく並ぶ。

```json
{"id":1,"start":1,"length":6,"raw":"\"name\"","edited":"\"name\""}
```

`length` は `raw` の長さと一致している必要がある。`edited` の長さに制限はない。空文字も許す。その場合、その範囲は削除される。

## 6. 書き戻し

1. 抜粋ファイルの形式を確認する。
2. 各件について、`start` から `length` 文字が `raw` と完全一致することを確認する。
3. 範囲がファイルの外、または別の件と重なる場合は、1 件も書き戻さず失敗する。
4. `start` の大きい件から `edited` を差し込む。先に後ろを置き換えるので、前の件の `start` はずれない。
5. 引用符の外、および `edited` が `raw` と同じ件は、バイト列として元のまま残る。

編集してよいのは `edited` だけである。`raw` や位置を変えると、入力を改変したあとに書き戻そうとしたときと同じように照合で失敗する。

## 7. 例

入力 `input.txt`:

```text
{"name":"太郎","note":"say \"hi\""}
```

`excerpt input.txt excerpt.jsonl` が書く抜粋:

```json
{"kind":"meta","tool":"excerptStringPutback","encoding":"utf-8","source":"input.txt"}
{"id":1,"start":1,"length":6,"raw":"\"name\"","edited":"\"name\""}
{"id":2,"start":8,"length":4,"raw":"\"太郎\"","edited":"\"太郎\""}
{"id":3,"start":13,"length":6,"raw":"\"note\"","edited":"\"note\""}
{"id":4,"start":20,"length":12,"raw":"\"say \\\"hi\\\"\"","edited":"\"say \\\"hi\\\"\""}
```

id 2 の `edited` だけを `"花子"` にすると、行は次のとおりになる。

```json
{"id":2,"start":8,"length":4,"raw":"\"太郎\"","edited":"\"花子\""}
```

`putback input.txt excerpt.jsonl output.txt` の結果:

```text
{"name":"花子","note":"say \"hi\""}
```

## 8. 対象外

- UTF-8 以外のエンコーディング
- 単一引用符と、バックスラッシュ以外のエスケープ規則
- C# の逐語的文字列、コメント、言語ごとの字句解析
- 入力ファイルを部分的にだけ読むこと。ファイル全体をメモリに読む
- 抜粋ファイルから行を削除して、一部の文字列だけを書き戻すこと。残す文字列は `edited` を `raw` のままにする
