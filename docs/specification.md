# excerptStringPutback 仕様

この文書は、書き出しと書き戻しの処理と、その間で受け渡す JSON を定義します。

このリポジトリのコマンド名は `excerptStringPutback` です。抽出した JSON の `program` には `excerptStringPutback` が入ります。`putback` は `program` を書き換えないので、`excerptTextPutback` が作った JSON も読めます。

先読み、後読み、後方参照は使えません。使えない構文は、抽出時にエラーになります。

## 1. テキストファイル

ツールが読むテキストファイルは次のいずれかです。

| `encoding` | BOM | 先頭バイト |
| --- | --- | --- |
| `utf-8` | なし | なし |
| `utf-8` | あり | `EF BB BF` |
| `utf-16le` | なし | なし |
| `utf-16le` | あり | `FF FE` |
| `utf-16be` | なし | なし |
| `utf-16be` | あり | `FE FF` |

BOM があるファイルは、その BOM で符号化を決めます。コマンドの `-encoding` と違っていても BOM を優先し、標準エラーにその旨を出します。

BOM が無いファイルは、自動では判別しません。`-encoding` が必要です。英語の UTF-16 LE は `41 00 42 00` のようになり、NUL を含む UTF-8 としても合法です。テキスト内の制御コードにも NUL があり得るので、`00` の多さでは区別しません。

次のファイルはエラーです。

- UTF-8 として不正なバイト列
- UTF-16 のバイト数が奇数
- 対になっていないサロゲート
- UTF-32 の BOM（`FF FE 00 00` または `00 00 FE FF`）

読み込んだ文字列は、改行を変換せず、制御バイトも残したまま正規表現にかけます。バイト位置はファイル先頭から数えます。BOM の長さも位置に含まれます。UTF-8 の BOM は 3 バイト、UTF-16 の BOM は 2 バイトです。

## 2. 正規表現

パターンは JSON の `pattern` に1つだけ書きます。フラグ用のフィールドはありません。フラグはパターン先頭のインラインフラグです。

| フラグ | 意味 |
| --- | --- |
| `(?m)` | `^` と `$` を行ごとにする |
| `(?s)` | `.` を改行にも一致させる |
| `(?i)` | 大文字と小文字を区別しない |
| `(?U)` | 量指定子を非貪欲にする |

複数は `(?ms)` のようにまとめ、パターンの先頭に置きます。ツールは常にすべての一致を取るので、グローバル検索を意味するフラグはありません。

`.` が一致しないのは `\n` だけです。`\r` には一致します。`(?m)` の `$` は `\n` の直前に一致します。そのため `(?m)^(?Key<id>[^=]+)=(?Source<value>.*)$` を CRLF の行にかけると、原文の末尾に `\r` が残ります。行末の CR を原文に入れないときは、原文を `[^\r\n]*` のように書きます。

`(?m)^(.*)` を、末尾が改行のファイルにかけると、最終改行の直後に幅ゼロの一致ができます。このファイル末尾の幅ゼロ一致だけは項目にしません。行の途中にある空行（幅ゼロでも、ファイル末尾ではないもの）は項目にします。

### 2.1 原文とキー

1つの一致は1つの項目です。1つの正規表現から複数の原文を抜いても、項目は分けません。

括弧の役割は、`(?` の直後の単語で決まります。大文字と小文字は区別します。`<>` の中の名前は、ASCII の英数字と `_` です。

- `(?Key<名前>...)` はキーです。出てくる順に `keys` へ並べます。
- `(?Source<名前>...)` は原文です。出てくる順に `sources` へ並べます。
- `(?:...)` はキャプチャしません。
- 名前の無い `(...)`、`(?P<名前>...)`、`(?<名前>...)`、`Key` でも `Source` でもない `(?単語<名前>...)` は抜き出しません。一致には参加します。エラーにはしません。
- `(?i)`、`(?m)`、`(?s)`、`(?U)`、`(?i:...)` はフラグです。

キーと原文の名前は1つの名前空間です。同じ名前が2回出てくるパターンはエラーです。先読み、後読み、後方参照はエラーです。

`(?Source<...>)` が1つも無いときは、一致全体が原文1つです。カタログの `sources` は `[""]` です。項目の `source` はその一致全体を1つ入れた配列、`before` と `after` は `[""]` です。

`sources` と項目の `source` は、配列の同じ位置が対応します。名前を項目へは書きません。その一致で `(?Source<...>)` が参加しなかった位置は、配列の位置をずらさないように残します。その位置の `source`、`before`、`after` は `""`、`byteStart` は `-1`、`byteLength` は `0` です。書き戻しではその位置を書きません。

`(?Source<名前>...)+` や `*` のように同じグループが繰り返すときは、そのグループの最後の繰り返しだけが残ります。

原文の範囲が重なるときはエラーです。入れ子の `(?Source<outer>(?Source<inner>...))` も重なりです。幅ゼロの原文が、別の原文の境界に隣り合うだけなら重なりではありません。

`before` の各要素は、一致全体のうち、同じ位置の原文より前です。`after` の各要素は、その原文より後ろです。参加した位置では `before[i]` + `source[i]` + `after[i]` が一致全体です。2つの原文のあいだは、前の原文の `after` と次の原文の `before` の両方に入ります。書き戻しが差し替えるのは各原文のバイト範囲だけなので、そのあいだの文字列はファイルに残ります。

例:

```text
pattern: (?m)^(?Key<key>[A-Z0-9_]+)=(?Source<value>.*)$
行:      MSG_01=Hello
```

| フィールド | 値 |
| --- | --- |
| `keys` | `["key"]` |
| `sources` | `["value"]` |
| 項目の `key` | `["MSG_01"]` |
| `before` | `["MSG_01="]` |
| `source` | `["Hello"]` |
| `after` | `[""]` |

原文が2つの例:

```text
pattern: (?m)^(?Key<id>\d+)\t(?Source<title>[^\t]*)\t(?Source<body>.*)
行:      15\tHello\tWorld
```

| フィールド | 値 |
| --- | --- |
| `keys` | `["id"]` |
| `sources` | `["title", "body"]` |
| 項目の `key` | `["15"]` |
| `before` | `["15\t", "15\tHello\t"]` |
| `source` | `["Hello", "World"]` |
| `after` | `["\tWorld", ""]` |

キーにする名前は、更新しても変わらない識別子だけにします。話者名や本文の一部に名前を付けると、そこが変わった行は `key` 方式では見つからず、後ろの方式へ回ります。

## 3. JSON

テキストファイル1つにつき JSON を1つ作ります。JSON 自体は常に UTF-8、BOM なし、インデント2スペースです。中身のある配列は要素を1行ずつにします。空の配列は `[]` のままです。`<` や `&` は `\u003c` の形にはしません。

未知のフィールドは、ツールが書き出すときに残しません。JSON に足しても、`putback` のあとには消えます。

フィールドは次の2段だけです。`program`、`formatVersion`、`toolVersion`、`fileVersion`、`note`、`pattern`、`keys`、`sources`、`replacementNames`、`used`、`methods` は先頭に1つずつです。`program` は JSON の最初のフィールドです。項目の中には繰り返しません。

### 3.0 フォーマットバージョン

現在の `formatVersion` は **2** です。この形式を書き出すツールのバージョンは **1.1.0** です。`excerptStringPutback version` でも確認できます。書き出した JSON の `program` には、そのファイルを作成したプログラムの名前が入ります。このツールが作成したときは `excerptStringPutback` です。`toolVersion` には、そのファイルを最後に書いたツールのバージョンが入ります。`fileVersion` は、利用者がこの JSON ファイル自身の版を自由に書く目印です。`note` は、利用者が JSON の値を自由に書く欄です。中身は読みません。ツールは `program` も `toolVersion` も `fileVersion` も `note` も、最新かどうかや書き戻しの判定に使いません。`program` や `toolVersion` や `fileVersion` や `note` が無いファイルも形式 2 として読みます。`formatVersion` 自身が 2 でないファイルは読みません。

| formatVersion | ツール | 内容 |
| --- | --- | --- |
| 1 | 1.0.0 | `(?P<名前>...)` をキー、最初の名前の無いキャプチャを原文にした初期形式。このツールは読まない |
| 2 | 1.1.0 | `(?Key<名前>...)` と `(?Source<名前>...)`。1マッチ1項目のまま `source` と `replacements` を配列にする |

JSON の形や、フィールドの意味、配列の並び、番号の数え方を変えるときは、必ず `formatVersion` を 1 増やしてからその形を書き出します。合わせてツールのバージョン番号も上げ、上の表に両方を残します。`formatVersion` を据え置いたまま、既存のファイルの意味が変わる変更をしてはなりません。

このツールは、自分の `formatVersion` と違う JSON を読むとエラーにします。フィールドが無い場合は 0 として扱い、同じくエラーです。

### 3.1 先頭のフィールド

| フィールド | 意味 |
| --- | --- |
| `program` | この JSON を作成したプログラムの名前。JSON の最初のフィールド。抽出直後は `excerptStringPutback`。書き戻しでは変えない。空でも受け取る。判定には使わない |
| `formatVersion` | JSON の形式番号。現在は 2。形式を変えたら 1 増やす |
| `toolVersion` | この JSON を最後に書いたツールのバージョン。抽出でも書き戻しでも、実行中のツールの番号で上書きする。形式の判定には使わない |
| `fileVersion` | この JSON ファイルの版。利用者が自由に書く文字列で、どのファイルが新しいかの目印にする。抽出直後は `""`。書き戻しでは変えない。中身の形式は問わない |
| `note` | 利用者が自由に書く欄。JSON の値なら何でもよい。抽出直後は `""`。このツールは中身を読まない。テキストへは書き込まない。入力に書いてあった値は、書き戻した JSON にこのツールの字下げで残す。欄が無いときは空文字を書く |
| `file` | 直近に読んだテキストファイルのパス。区切りは `/` |
| `encoding` | `utf-8`、`utf-16le`、`utf-16be` のいずれか |
| `bom` | そのファイルに BOM があったか |
| `pattern` | 抽出と書き戻しの両方で使う正規表現 |
| `keys` | `(?Key<名前>...)` の名前。左から並ぶ。無ければ `[]` |
| `sources` | `(?Source<名前>...)` の名前。左から並ぶ。原文グループが無いときは `[""]`。項目の `source` と同じ位置が対応する |
| `replacementNames` | 変更後文字列の番号の表示名。1番が先頭。抽出直後は `["changed"]`。書き戻しの判定には使わない |
| `used` | `-number` を省略したときに書き戻す変更後文字列の番号。抽出直後は `1`。書き戻しのあとには、その回の番号で上書きする |
| `methods` | 有効な方式。省略時は6つ全部。`[]` は全部無効 |
| `entries` | 切り出した文字列。ファイル順 |

`methods` に書く順序は保存時に実行順へ並べ直します。実行順は常に `key`、`offset`、`exact`、`context`、`align`、`revised` です。

### 3.2 項目のフィールド

| フィールド | 意味 |
| --- | --- |
| `key` | `keys` と同じ順の、その一致の識別子。個数は `keys` と一致する |
| `before` | 一致全体のうち、同じ位置の原文の前。`source` と同じ長さ |
| `source` | 原文の配列。NFC にはしない。`sources` と同じ長さ |
| `after` | 一致全体のうち、同じ位置の原文の後。`source` と同じ長さ |
| `previousSource` | `source` と同じ長さ。変わっていない位置は `""`。抽出直後はすべて `""`。いずれかの位置が変わった項目では、変わった位置に変わる前の文字列を入れる |
| `replacements` | 変更後文字列。外側が番号、内側が `source` と同じ位置。1番が先頭。抽出直後は、その項目の `source` を1行だけ入れた配列 |
| `byteStart` | 各原文のファイル先頭からのバイト位置。参加しなかった位置は `-1` |
| `byteLength` | そのバイト長。参加しなかった位置は `0` |
| `status` | `exact`、`revised`、`unmatched`、または抽出直後の `""` |
| `matchedBy` | その回の書き戻しで使った方式名。書いていなければ `""` |

`replacements` の `"やあ\\n世界"` は、テキスト内ではバックスラッシュと `n` の2文字です。本物の改行を含む `source` は、JSON 上では `\n` または `\r` です。NUL などは `\u0000` のようにエスケープします。引用符の内側に、エスケープしていない改行は置けません。

`source` は原文のまま比較します。書き込む変更後文字列だけを NFC にします。周囲のバイトは、符号化し直しても同じになる範囲ではそのまま残します。

### 3.3 変更後文字列の番号

番号は 1 から数えます。書き戻し1回につき、ファイル全体で1つの番号だけを使います。項目ごとに選ぶフィールドはありません。

- その番号の行が `replacements` に無い項目は、テキストファイルへ書きません。
- ある行の内側が `source` より短いときは、書いてある位置だけを書き、足りない位置は書きません。
- 内側の文字列が空の位置は、その原文の範囲を空文字で置き換えます。
- `byteStart` が `-1` の位置は書きません。
- 書かなかった項目の `replacements` は残します。
- 実行した番号は、終わったときに `used` へ上書きします。
- `-number` を省略したときは `used` を使います。`used` が 0 で `-number` も無いときは、そのファイルは書き戻さずエラーにします。

途中の変更後文字列を消すときは、全項目の同じ番号と、`replacementNames` の同じ位置をまとめて消します。番号は外側の配列の位置そのものなので、途中を消すと後ろの番号が繰り上がります。

## 4. 書き出し

`excerpt` はテキストファイルと正規表現から、新しい JSON を作ります。既存の JSON に入っている変更後文字列は引き継ぎません。変更後文字列を残したまま更新するのは `putback` だけです。

手順は次のとおりです。

1. ファイルを第1節の規則で読む。
2. `pattern` をコンパイルし、名前と原文のキャプチャを決める。
3. ファイルの前から順に、重ならない一致を取る。
4. 各一致から `key`、`before`、`source`、`after`、`byteStart`、`byteLength` を作る。
5. `formatVersion` は 2、`program` は `excerptStringPutback`、`toolVersion` は実行中のツールのバージョン、`fileVersion` と `note` は空文字、各項目の `replacements` は `source` を1行だけ入れた配列、`replacementNames` は `["changed"]`、`previousSource` は `source` と同じ長さの空文字、`status` と `matchedBy` は空文字、`used` は 1 にする。`sources` はパターンの原文名、原文グループが無いときは `[""]` にする。
6. `methods` は、コマンドで無効にしていない方式を実行順で入れる。

`changed` は、1番の変更後文字列の表示名です。中身は原文の複製で、人が書き換えてから書き戻します。`replacementNames` は対応づけには使いません。原文が空の位置は、変更後文字列も空になります。空の変更後文字列も書き戻し、その位置を空にします。

原文の範囲が重なる一致はエラーです。通常の検索は重ならない一致だけを返すので、通常のパターンでは起きません。

## 5. 書き戻し

`putback` は、カタログの `pattern` を今のテキストファイルに掛け直し、既存の項目と対応づけます。テキストファイルを `-o` へ書き、カタログの対応づけ結果を更新します。`-o` と入力のテキストファイルが同じパスのときは、そのファイルを更新します。別のパスのときは、元のテキストファイルは変更しません。

読む符号化はカタログの `encoding` を指定として使い、ファイル側に BOM があれば BOM を優先します。出力の符号化と BOM は、そのとき実際に読んだものに合わせ、カタログの `encoding` と `bom` と `file` もそれに更新します。

有効な方式はカタログの `methods` です。`-disable` で外した方式は、その1回だけ使いません。保存する `methods` からは消しません。

対応づけは、有効なものだけを次の順で行います。前の方式が使った項目と、今のファイル側の枠は、後ろの方式では使いません。各方式は、自分の規則で一意に決まるときだけ結びます。

### 5.1 `key`

`keys` が空なら何もしません。カタログの `keys` に、今のパターンへ存在しない名前があるときも何もせず、警告を出します。

今の一致から名前で値を集め、カタログの `keys` の順に並べます。その配列が項目の `key` と完全に一致し、古い側と新しい側の両方でその配列が1回だけなら結びます。同じ配列が2件以上あるものは、この方式では書きません。

文面が変わっていても、識別子が一致すれば結びます。

### 5.2 `offset`

項目に記録した各位置の `byteStart`、`byteLength`、`source` が、今のファイルの1つの一致の同じ位置とすべて一致し、その範囲が今のファイル上でも同じ文字列に復号できるとき結びます。`byteStart` が `-1` の位置は、両側とも参加していないときに一致します。その条件を満たす未使用の一致が1つだけのときに結びます。

ファイルの前にバイトが増えると、この方式は外れます。あとの方式が続きを見ます。前後の文字が変わっていても、原文のバイト範囲と中身が同じなら、この方式が先に結びます。前後で区別したいときは `-disable offset` を使います。

### 5.3 `exact`

まだ残っている項目と一致のうち、`source` の配列が古い側と新しい側の両方で1回だけ現れるものを結びます。位置が前後にずれていても結びます。同じ配列が2回以上あるものは、この方式では書きません。

### 5.4 `context`

`before` と `after` の要素に1つでも空でない文字列があるものだけを見ます。`before`、`source`、`after` の配列が古い側と新しい側の両方で1回だけ一致すれば結びます。`before` と `after` の要素がすべて空の項目は、この方式では何もしません。

### 5.5 `align` と `revised`

ここまでで結びつかなかった行を、ファイル順の差分で見ます。すでに結んだ対のうち、古い順と新しい順が交差しないものを杭にします。杭と杭のあいだだけを、それぞれ別に比較します。杭の反対側にある行同士は結びません。

例として、古い並びが `keep-a`、`move-me`、`keep-b`、新しい並びが `NEW`、`keep-a`、`keep-b` のとき、`keep-a` と `keep-b` が杭です。`NEW` は先頭の追加、`move-me` は削除なので、互いには書きません。

`align` が有効なら、区間の中で原文が同じ行を最長共通部分として結びます。`matchedBy` は `align`、`status` は `exact` です。

`revised` が有効なら、その共通部分をさらに杭にして、削除と追加の本数が同じ区間を上から順に結びます。本数が違う区間は書きません。`matchedBy` は `revised` です。`source` の配列が同じなら `status` は `exact` で、`previousSource` はすべて空文字です。いずれかの位置が変わっていれば `status` は `revised` です。変わった位置の `previousSource` には変わる前の文字列を残し、変わっていない位置は `""` です。`source` は今のテキスト側の配列に更新します。

`align` を無効にして `revised` だけを有効にすると、杭と杭のあいだ全体が1つの区間になります。その区間の本数が同じなら、上から順に結びます。前の方式を無効にすると区間が広がり、ファイルの広い範囲を順番で結ぶことがあります。文面の変わった枠へ変更後文字列を載せないときは `revised` を無効にします。

更新で増えた一致は、テキストファイル側の原文のまま残します。JSON には自動では追加しません。消えた一致の項目は JSON に残し、`status` を `unmatched`、`matchedBy` を空、`previousSource` を `source` と同じ長さの空文字にします。`source` は更新しません。`replacements` は残します。

カタログの `sources` の並びが、今のパターンの原文名と違うときは警告を出します。`key` 方式は、この警告では無効にしません。書き戻しのあと、`sources` は今のパターンの名前で上書きします。原文グループが無いときは `[""]` です。

### 5.6 実際に書くとき

対応が決まった項目でも、選んだ番号の行が `replacements` に無いときは、テキストファイルは変えません。その項目は `status` が `unmatched`、`matchedBy` が空です。

選んだ番号の行がある項目は、その行に書いてある位置だけを差し替えます。空文字も含めます。`byteStart` が `-1` の位置は残します。差し替えるのはその原文のバイト範囲だけです。一致の外側と、原文と原文のあいだは残します。差し替えは開始位置、長さ、配列の位置の順に組み立て、結果を読んだときと同じ符号化と BOM で出力します。

書き込んだ項目は次のように更新します。

- `source`、`before`、`after`、`byteStart`、`byteLength` は、書き戻す前の入力ファイル上の現在の一致に合わせる
- `key` は、今のパターンからカタログの `keys` の順で取り直せるときに更新する
- `source` の配列が同じなら `status` は `exact`、`previousSource` はすべて空文字
- いずれかの位置が変わったなら `status` は `revised`、変わった位置の `previousSource` は更新前の文字列、変わっていない位置は `""`
- `matchedBy` は、その項目を結んだ方式名

`byteStart` は出力ファイルではなく、その回に読んだ入力ファイル上の位置です。書き込んだ変更後文字列のバイト長が原文と異なる出力ファイルに、次の回の `offset` がそのまま当たるとは限りません。当たらないときは後ろの方式が探します。

`matchedBy` と `status` は、書き戻しのたびに全項目を書き直します。JSON の変更後文字列を手で直しても、次に書き戻すまでは `matchedBy` は変わりません。書き戻した JSON の `toolVersion` は、その回を実行したツールのバージョンに更新します。`program` と `fileVersion` は、入力の JSON に書いてあった文字列のまま残します。`note` は書き戻しで読みません。入力に書いてあった JSON の値を残します。無ければ空文字を書きます。

書き戻す項目が0件でも、符号化し直したテキストファイルを出力します。変更が無ければ、入力と同じバイト列になります。

## 6. コマンド

```text
excerptStringPutback excerpt [-language en|ja] -encoding <符号化> -pattern <正規表現> [-disable <方式>] -o <出力.json> <テキストファイル>
excerptStringPutback excerpt [-language en|ja] -encoding <符号化> -pattern-file <ファイル> [-disable <方式>] -o <出力.json> <テキストファイル>
excerptStringPutback putback [-language en|ja] -number <番号> -o <出力ファイル> [-json-out <JSON>] [-disable <方式>] <カタログ.json> <テキストファイル>
```

| 終了コード | 意味 |
| --- | --- |
| 0 | 完了。対応しなかった項目があっても 0 |
| 1 | ファイル、符号化、正規表現、JSON のエラー |
| 2 | 引数の不足や未知のコマンド |

標準出力には結果のファイルを書きません。経過と警告は標準エラーです。エラー、警告、使い方などのメッセージは、`-language` で英語（`en`）と日本語（`ja`）に切り替えます。省略したときは OS の表示言語に合わせます。表示言語が日本語ならメッセージは日本語、英語なら英語、それ以外は英語です。`-pattern-file` は先頭の UTF-8 BOM を外し、末尾の改行を1つだけ除いてパターンにします。

`-disable` はカンマ区切りです。未知の方式名はエラーです。

## 7. 人が変えてよいフィールド

人が変えてよいのは、原則として `replacementNames`、`fileVersion`、`note`、各項目の `replacements` です。`fileVersion` は、その JSON がどの版かを人が見分けるための文字列です。`note` には JSON の値を自由に書けます。このツールは `note` の中身を読まず、テキストへも書き込みません。`source`、`key`、`before`、`after`、バイト位置、`pattern`、符号化は、書き戻しの対応づけに使います。

JSON は UTF-8（BOM なし）で保存します。

このツールは、その JSON を `putback` で受け取ります。
