# excerptStringPutback 仕様

この文書は、書き出しと書き戻しの処理と、その間で受け渡す JSON を定義します。

このリポジトリのコマンド名は `excerptStringPutback` です。抽出した JSON の `program` には `excerptStringPutback` が入ります。`write` は `program` を書き換えないので、`excerptTextPutback` が作った JSON も読めます。

正規表現の構文は Go の `regexp`（RE2）に合わせます。先読み、後読み、後方参照は使えません。使えない構文は、抽出時にエラーになります。

## 1. テキストファイル

ツールが読むテキストファイルは次のいずれかです。

| `encoding` | BOM | 先頭バイト |
| --- | --- | --- |
| `utf-8` | なし | なし |
| `utf-8` | あり | `EF BB BF` |
| `utf-16le` | なし | なし |
| `utf-16le` | あり | `FF FE` |
| `utf-16be` | なし | なし |
| `utf-16be` | あり | `FE FF` |

BOM があるファイルは、その BOM で符号化を決めます。コマンドの `-encoding` と違っていても BOM を優先し、標準エラーにその旨を出します。

BOM が無いファイルは、自動では判別しません。`-encoding` が必要です。英語の UTF-16 LE は `41 00 42 00` のようになり、NUL を含む UTF-8 としても合法です。テキスト内の制御コードにも NUL があり得るので、`00` の多さでは区別しません。

次のファイルはエラーです。

- UTF-8 として不正なバイト列
- UTF-16 のバイト数が奇数
- 対になっていないサロゲート
- UTF-32 の BOM（`FF FE 00 00` または `00 00 FE FF`）

読み込んだ文字列は、改行を変換せず、制御バイトも残したまま正規表現にかけます。バイト位置はファイル先頭から数えます。BOM の長さも位置に含まれます。UTF-8 の BOM は 3 バイト、UTF-16 の BOM は 2 バイトです。

## 2. 正規表現

パターンは JSON の `pattern` に1つだけ書きます。フラグ用のフィールドはありません。フラグはパターン先頭のインラインフラグです。

| フラグ | 意味 |
| --- | --- |
| `(?m)` | `^` と `$` を行ごとにする |
| `(?s)` | `.` を改行にも一致させる |
| `(?i)` | 大文字と小文字を区別しない |
| `(?U)` | 量指定子を非貪欲にする |

複数は `(?ms)` のようにまとめ、パターンの先頭に置きます。ツールは常にすべての一致を取るので、グローバル検索を意味するフラグはありません。

`.` が一致しないのは `\n` だけです。`\r` には一致します。`(?m)` の `$` は `\n` の直前に一致します。そのため `(?m)^(?P<id>[^=]+)=(.*)$` を CRLF の行にかけると、キャプチャの末尾に `\r` が残ります。行末の CR を原文に入れないときは、キャプチャを `[^\r\n]*` のように書きます。

`(?m)^(.*)` を、末尾が改行のファイルにかけると、最終改行の直後に幅ゼロの一致ができます。このファイル末尾の幅ゼロ一致だけは項目にしません。行の途中にある空行（幅ゼロでも、ファイル末尾ではないもの）は項目にします。

### 2.1 原文とキー

括弧には3種類あります。

- `(?P<名前>...)` は名前付きキャプチャです。パターンに出てくる名前を、左からすべてキーにします。
- `(...)` は名前の無いキャプチャです。そのうち最初のものが原文です。
- `(?:...)` や先読みに使う括弧はキャプチャではありません。原文にもキーにもなりません。

名前の無いキャプチャが1つも無いときは、一致全体が原文です。名前付きキャプチャが無いときは、キーは空です。同じ名前が2回出てくるパターンはエラーです。

名前付きグループが一致しなかった場合、その位置の値は空文字です。配列の長さは名前の個数と揃えます。

`before` は、一致全体のうち原文より前の文字列です。`after` は原文より後ろの文字列です。どちらも空になることがあります。空でも項目としては有効です。

例:

```text
pattern: (?m)^(?P<chapter>\d+)\t(?P<id>\d+)\t(.*)
行:      1\t15\tHello
```

| フィールド | 値 |
| --- | --- |
| `keys` | `["chapter", "id"]` |
| 項目の `key` | `["1", "15"]` |
| `before` | `"1\t15\t"` |
| `source` | `"Hello"` |
| `after` | `""` |

キーにする名前は、更新しても変わらない識別子だけにします。話者名や本文の一部に名前を付けると、そこが変わった行は `key` 方式では見つからず、後ろの方式へ回ります。

## 3. JSON

テキストファイル1つにつき JSON を1つ作ります。JSON 自体は常に UTF-8、BOM なし、インデント2スペースです。`<` や `&` は `\u003c` の形にはしません。

未知のフィールドは、ツールが書き出すときに残しません。JSON に足しても、`write` のあとには消えます。

フィールドは次の2段だけです。`program`、`formatVersion`、`toolVersion`、`fileVersion`、`pattern`、`names`、`keys`、`used`、`methods` は先頭に1つずつです。`program` は JSON の最初のフィールドです。項目の中には繰り返しません。

### 3.0 フォーマットバージョン

現在の `formatVersion` は **1** です。この形式を書き出すツールのバージョンは **1.0.0** です。`excerptStringPutback version` でも確認できます。書き出した JSON の `program` には、そのファイルを作成したプログラムの名前が入ります。このツールが作成したときは `excerptStringPutback` です。`toolVersion` には、そのファイルを最後に書いたツールのバージョンが入ります。`fileVersion` は、利用者がこの JSON ファイル自身の版を自由に書く目印です。ツールは `program` も `toolVersion` も `fileVersion` も、最新かどうかや書き戻しの判定に使いません。これらの項目を足したときも `formatVersion` は 1 のままです。`program` や `toolVersion` や `fileVersion` が無いファイルも形式 1 として読みます。

| formatVersion | ツール | 内容 |
| --- | --- | --- |
| 1 | 1.0.0 | 初期形式。この文書のフィールド定義 |

JSON の形や、フィールドの意味、配列の並び、番号の数え方を変えるときは、必ず `formatVersion` を 1 増やしてからその形を書き出します。合わせてツールのバージョン番号も上げ、上の表に両方を残します。`formatVersion` を据え置いたまま、既存のファイルの意味が変わる変更をしてはなりません。

このツールは、自分の `formatVersion` と違う JSON を読むとエラーにします。フィールドが無い場合は 0 として扱い、同じくエラーです。

```json
{
  "program": "excerptStringPutback",
  "formatVersion": 1,
  "toolVersion": "1.0.0",
  "fileVersion": "3",
  "file": "data/script.txt",
  "encoding": "utf-8",
  "bom": false,
  "pattern": "(?m)^(?P<key>[A-Z0-9_]+)=(.*)$",
  "keys": ["key"],
  "names": ["ですます", "常体"],
  "used": 2,
  "methods": ["key", "offset", "exact", "context", "align", "revised"],
  "entries": [
    {
      "key": ["MSG_01"],
      "before": "MSG_01=",
      "source": "Hello",
      "after": "",
      "previousSource": "",
      "target": ["こんにちは", "やあ\\n世界"],
      "byteStart": 7,
      "byteLength": 5,
      "status": "exact",
      "matchedBy": "key"
    },
    {
      "key": ["MSG_03"],
      "before": "MSG_03=",
      "source": "Yes",
      "after": "",
      "previousSource": "",
      "target": ["はい"],
      "byteStart": 39,
      "byteLength": 3,
      "status": "unmatched",
      "matchedBy": ""
    }
  ]
}
```

### 3.1 先頭のフィールド

| フィールド | 意味 |
| --- | --- |
| `program` | この JSON を作成したプログラムの名前。JSON の最初のフィールド。抽出直後は `excerptStringPutback`。書き戻しでは変えない。空でも受け取る。判定には使わない |
| `formatVersion` | JSON の形式番号。現在は 1。形式を変えたら 1 増やす |
| `toolVersion` | この JSON を最後に書いたツールのバージョン。抽出でも書き戻しでも、実行中のツールの番号で上書きする。形式の判定には使わない |
| `fileVersion` | この JSON ファイルの版。利用者が自由に書く文字列で、どのファイルが新しいかの目印にする。抽出直後は `""`。書き戻しでは変えない。中身の形式は問わない |
| `file` | 直近に読んだテキストファイルのパス。区切りは `/` |
| `encoding` | `utf-8`、`utf-16le`、`utf-16be` のいずれか |
| `bom` | そのファイルに BOM があったか |
| `pattern` | 抽出と書き戻しの両方で使う正規表現 |
| `keys` | 名前付きキャプチャの名前。左から並ぶ。無ければ `[]` |
| `names` | 変更後文字列の番号の表示名。1番が先頭。抽出直後は `["changed"]`。書き戻しの判定には使わない |
| `used` | `-number` を省略したときに書き戻す変更後文字列の番号。抽出直後は `1`。書き戻しのあとには、その回の番号で上書きする |
| `methods` | 有効な方式。省略時は6つ全部。`[]` は全部無効 |
| `entries` | 切り出した文字列。ファイル順 |

`methods` に書く順序は保存時に実行順へ並べ直します。実行順は常に `key`、`offset`、`exact`、`context`、`align`、`revised` です。

### 3.2 項目のフィールド

| フィールド | 意味 |
| --- | --- |
| `key` | `keys` と同じ順の、その行の識別子。個数は `keys` と一致する |
| `before` | 一致全体のうち原文の前 |
| `source` | 原文。NFC にはしない |
| `after` | 一致全体のうち原文の後 |
| `previousSource` | 直前の書き戻しで原文が変わっていたときの、変わる前の `source`。同じなら `""` |
| `target` | 変更後文字列の配列。1番が先頭。抽出直後は、その項目の `source` と同じ文字列を1つ入れた配列 |
| `byteStart` | `source` のファイル先頭からのバイト位置 |
| `byteLength` | そのバイト長 |
| `status` | `exact`、`revised`、`unmatched`、または抽出直後の `""` |
| `matchedBy` | その回の書き戻しで使った方式名。書いていなければ `""` |

`target` の `"やあ\\n世界"` は、テキスト内ではバックスラッシュと `n` の2文字です。本物の改行を含む `source` は、JSON 上では `\n` または `\r` です。NUL などは `\u0000` のようにエスケープします。引用符の内側に、エスケープしていない改行は置けません。

`source` は原文のまま比較します。書き込む変更後文字列だけを NFC にします。周囲のバイトは、符号化し直しても同じになる範囲ではそのまま残します。

### 3.3 変更後文字列の番号

番号は 1 から数えます。書き戻し1回につき、ファイル全体で1つの番号だけを使います。項目ごとに選ぶフィールドはありません。

- その番号の要素が配列に無い項目は、テキストファイルへ書きません。
- その番号の文字列が空の項目も書きません。
- 書かなかった項目の `target` は残します。
- 実行した番号は、終わったときに `used` へ上書きします。
- `-number` を省略したときは `used` を使います。`used` が 0 で `-number` も無いときは、そのファイルは書き戻さずエラーにします。

途中の変更後文字列を消すときは、全項目の同じ位置と、`names` の同じ位置をまとめて消します。番号は配列の位置そのものなので、途中を消すと後ろの番号が繰り上がります。

## 4. 書き出し

`extract` はテキストファイルと正規表現から、新しい JSON を作ります。既存の JSON に入っている変更後文字列は引き継ぎません。変更後文字列を残したまま更新するのは `write` だけです。

手順は次のとおりです。

1. ファイルを第1節の規則で読む。
2. `pattern` をコンパイルし、名前と原文のキャプチャを決める。
3. ファイルの前から順に、重ならない一致を取る。
4. 各一致から `key`、`before`、`source`、`after`、`byteStart`、`byteLength` を作る。
5. `formatVersion` は 1、`program` は `excerptStringPutback`、`toolVersion` は実行中のツールのバージョン、`fileVersion` は空文字、各項目の `target` は `source` と同じ文字列を1つ入れた配列、`names` は `["changed"]`、`previousSource` と `status` と `matchedBy` は空文字、`used` は 1 にする。
6. `methods` は、コマンドで無効にしていない方式を実行順で入れる。

`changed` は、1番の変更後文字列の表示名です。中身は原文の複製で、人が書き換えてから書き戻します。`names` は対応づけには使いません。原文が空の項目は、変更後文字列も空になります。空の変更後文字列は書き戻しません。

原文の範囲が重なる一致はエラーです。RE2 の通常の検索は重ならない一致だけを返すので、通常のパターンでは起きません。

## 5. 書き戻し

`write` は、カタログの `pattern` を今のテキストファイルに掛け直し、既存の項目と対応づけます。元のテキストファイルは変更しません。新しいテキストファイルを `-o` へ書き、カタログの対応づけ結果を更新します。

読む符号化はカタログの `encoding` を指定として使い、ファイル側に BOM があれば BOM を優先します。出力の符号化と BOM は、そのとき実際に読んだものに合わせ、カタログの `encoding` と `bom` と `file` もそれに更新します。

有効な方式はカタログの `methods` です。`-disable` で外した方式は、その1回だけ使いません。保存する `methods` からは消しません。

対応づけは、有効なものだけを次の順で行います。前の方式が使った項目と、今のファイル側の枠は、後ろの方式では使いません。各方式は、自分の規則で一意に決まるときだけ結びます。

### 5.1 `key`

`keys` が空なら何もしません。カタログの `keys` に、今のパターンへ存在しない名前があるときも何もせず、警告を出します。

今の一致から名前で値を集め、カタログの `keys` の順に並べます。その配列が項目の `key` と完全に一致し、古い側と新しい側の両方でその配列が1回だけなら結びます。同じ配列が2件以上あるものは、この方式では書きません。

文面が変わっていても、識別子が一致すれば結びます。

### 5.2 `offset`

項目に記録した `byteStart` と `byteLength` の範囲が、今のファイルでも同じ `source` に復号でき、その範囲が今の正規表現の原文のキャプチャと一致するとき結びます。同じ開始位置のキャプチャが2つあるときは結びません。

ファイルの前にバイトが増えると、この方式は外れます。あとの方式が続きを見ます。前後の文字が変わっていても、原文のバイト範囲と中身が同じなら、この方式が先に結びます。前後で区別したいときは `-disable offset` を使います。

### 5.3 `exact`

まだ残っている項目と枠のうち、`source` が古い側と新しい側の両方で1回だけ現れるものを結びます。位置が前後にずれていても結びます。同じ原文が2回以上あるものは、この方式では書きません。

### 5.4 `context`

`before` と `after` の少なくとも片方が空でないものだけを見ます。`before` + `source` + `after` が古い側と新しい側の両方で1回だけ一致すれば結びます。両方が空の項目は、この方式では何もしません。

### 5.5 `align` と `revised`

ここまでで結びつかなかった行を、ファイル順の差分で見ます。すでに結んだ対のうち、古い順と新しい順が交差しないものを杭にします。杭と杭のあいだだけを、それぞれ別に比較します。杭の反対側にある行同士は結びません。

例として、古い並びが `keep-a`、`move-me`、`keep-b`、新しい並びが `NEW`、`keep-a`、`keep-b` のとき、`keep-a` と `keep-b` が杭です。`NEW` は先頭の追加、`move-me` は削除なので、互いには書きません。

`align` が有効なら、区間の中で原文が同じ行を最長共通部分として結びます。`matchedBy` は `align`、`status` は `exact` です。

`revised` が有効なら、その共通部分をさらに杭にして、削除と追加の本数が同じ区間を上から順に結びます。本数が違う区間は書きません。`matchedBy` は `revised` です。原文が変わっていれば `status` は `revised` で、`previousSource` に変わる前の `source` を残し、`source` は今のテキスト側の文字列に更新します。

`align` を無効にして `revised` だけを有効にすると、杭と杭のあいだ全体が1つの区間になります。その区間の本数が同じなら、上から順に結びます。前の方式を無効にすると区間が広がり、ファイルの広い範囲を順番で結ぶことがあります。文面の変わった枠へ変更後文字列を載せないときは `revised` を無効にします。

更新で増えた文字列は、テキストファイル側の原文のまま残します。JSON には自動では追加しません。消えた文字列の項目は JSON に残し、`status` を `unmatched`、`matchedBy` を空にします。変更後文字列の配列は残します。

### 5.6 実際に書くとき

対応が決まった項目でも、選んだ番号の変更後文字列が無い、または空文字なら、テキストファイルは変えません。その項目は `status` が `unmatched`、`matchedBy` が空です。

変更後文字列がある項目は、原文のキャプチャの範囲だけを NFC の変更後文字列で差し替えます。一致の外側と、`before` / `after` に当たる部分は残します。差し替えは位置の若い順に組み立て、結果を読んだときと同じ符号化と BOM で出力します。

書き込んだ項目は次のように更新します。

- `source`、`before`、`after`、`byteStart`、`byteLength` は、書き戻す前の入力ファイル上の現在の一致に合わせる
- `key` は、今のパターンからカタログの `keys` の順で取り直せるときに更新する
- 原文が同じなら `status` は `exact`、`previousSource` は空
- 原文が変わったなら `status` は `revised`、`previousSource` は更新前の `source`
- `matchedBy` は、その項目を結んだ方式名

`byteStart` は出力ファイルではなく、その回に読んだ入力ファイル上の位置です。書き込んだ変更後文字列のバイト長が原文と異なる出力ファイルに、次の回の `offset` がそのまま当たるとは限りません。当たらないときは後ろの方式が探します。

`matchedBy` と `status` は、書き戻しのたびに全項目を書き直します。JSON の変更後文字列を手で直しても、次に書き戻すまでは `matchedBy` は変わりません。書き戻した JSON の `toolVersion` は、その回を実行したツールのバージョンに更新します。`program` と `fileVersion` は、入力の JSON に書いてあった文字列のまま残します。

書き戻す項目が0件でも、符号化し直したテキストファイルを出力します。変更が無ければ、入力と同じバイト列になります。

## 6. コマンド

```text
excerptStringPutback extract -encoding <符号化> -pattern <正規表現> [-disable <方式>] -o <出力.json> <テキストファイル>
excerptStringPutback extract -encoding <符号化> -pattern-file <ファイル> [-disable <方式>] -o <出力.json> <テキストファイル>
excerptStringPutback write -number <番号> -o <出力ファイル> [-json-out <JSON>] [-disable <方式>] <カタログ.json> <テキストファイル>
```

| 終了コード | 意味 |
| --- | --- |
| 0 | 完了。対応しなかった項目があっても 0 |
| 1 | ファイル、符号化、正規表現、JSON のエラー |
| 2 | 引数の不足や未知のコマンド |

標準出力には結果のファイルを書きません。経過と警告は標準エラーです。`-pattern-file` は先頭の UTF-8 BOM を外し、末尾の改行を1つだけ除いてパターンにします。

`-disable` はカンマ区切りです。未知の方式名はエラーです。

## 7. 人が変えてよいフィールド

人が変えてよいのは、原則として `names`、`fileVersion`、各項目の `target` です。`fileVersion` は、その JSON がどの版かを人が見分けるための文字列です。`source`、`key`、`before`、`after`、バイト位置、`pattern`、符号化は、書き戻しの対応づけに使います。

JSON は UTF-8（BOM なし）で保存します。

このツールは、その JSON を `write` で受け取ります。
